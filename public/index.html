La idea

Bitácora

Cómo lo hicimos

  1. Cuentas con el correo de la UCE. GitHub, GitLab y Atlassian con el correo institucional. En la PC fijamos el usuario de cada plataforma en el repositorio, porque el administrador de credenciales tenía guardada otra cuenta.
  2. Repositorios. En GitHub, un repositorio público. En GitLab, un grupo (grupo2-versionamiento-uce) con el proyecto dentro; tuvimos que hacer público el grupo, porque un proyecto público no puede estar en un grupo privado.
  3. Pipelines. El workflow de GitHub y el .gitlab-ci.yml: validar y luego publicar. El primer despliegue en GitHub tardó 41 segundos.
  4. Variables. ENTORNO creada en cada plataforma (en GitLab como protegida). El commit lo ponen las variables predefinidas.
  5. Reglas. Ruleset proteger-main: PR obligatorio, check validate obligatorio, sin force push ni borrado, sin excepciones.
  6. PR #1 · flujo normal. Enlace a Confluence y QR del sitio. validate en verde, merge y publicación en 49 segundos.
  7. PR #2 · corregimos el validador. Al preparar la prueba de error vimos que el preset standard no revisaba accesibilidad; agregamos el preset a11y.
  8. PR #3 · error provocado. Quitamos el texto alternativo del QR: validate falló y GitHub bloqueó el merge. Lo dejamos abierto como evidencia.
  9. Mediciones. Con scripts/medir.sh: el script mira la versión publicada cada 5 segundos y guarda cuánto tardó en cambiar.

Evidencia

Resultados medidos

Medimos el tiempo de entrega: los segundos desde que se aprueba un cambio hasta que se ve en el sitio publicado. Es una de las cuatro métricas DORA (Forsgren, Humble y Kim, 2018). Cada integrante suma 5 despliegues por plataforma; la tabla se completa con los datos de todo el grupo.

PlataformaDespliegues medidosTiempo de entrega (promedio)Mínimo y máximo
GitHub Pages347 s44 s y 49 s
GitLab Pages0PendientePendiente

Con tres mediciones todavía no se puede concluir nada; por eso la meta es llegar a 20 despliegues por plataforma entre los cuatro.
