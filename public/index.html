Gestión de versionamiento

Una página web con nuestra investigación, guardada con Git, que se publica sola en GitHub y en GitLab cada vez que se aprueba un cambio. Además, medimos cuál de las dos plataformas lo hace mejor.

Ver la presentación Leer la investigación Ver la ruta de trabajo

La idea

No solo explicamos GitHub y GitLab: los usamos para lo mismo y los medimos

El mismo sitio que estás viendo está desplegado en dos plataformas, cada una con su propio pipeline. Cada vez que el grupo aprueba un cambio, un robot valida el HTML y, si todo está bien, lo publica. El pie de página muestra en qué plataforma estás, qué versión (commit) se desplegó y cuándo.

Conceptos básicos

Las piezas del trabajo

Git

El cuaderno de versiones

Guarda cada versión del trabajo y quién la hizo. Funciona en la computadora, incluso sin internet.

Commit

Una foto del proyecto

El estado del proyecto en un momento dado, con una nota de qué cambió.

GitHub / GitLab

Dos bibliotecas

Plataformas en la nube donde guardamos la copia del trabajo y colaboramos.

Pipeline (CI/CD)

Un robot que revisa

Revisa el trabajo y, si está bien, lo pone en la vitrina: GitHub Actions y GitLab CI.

Pages

La vitrina

El hosting donde cualquiera ve el trabajo con un link: GitHub Pages y GitLab Pages.

Qué usamos

Tecnologías y herramientas

Versionamiento

Git

Historial, ramas, tags y dos remotos: origin (GitHub) y gitlab.

Plataforma

GitHub

Repositorio principal, pull requests, rulesets, Actions y Pages.

Plataforma

GitLab

Segundo destino: CI/CD con .gitlab-ci.yml, ramas protegidas y Pages.

Calidad

IDE del proyecto, con Git, GitHub y GitLab integrados.

Jira para las tareas por etapa; Confluence para el SRS, la ruta y las decisiones.

Medición

Web
